Layer 1 — Email Trigger
Trigger: Email sent to urti.agent@indigo.in

Email Parser Agent extracts:

IGA ID, Crew Name, From Date, To Date, No. of Days

Checks if attachments (Medical Cert + Fitness Cert) are present

If attachments missing → auto-reject, notify sender, stop

Layer 2 — Idempotency Gates
Gate 1 (Auto): Query internal DB

text
IF status = PROCESSED → auto-reject, send "already processed" mail
IF status = PENDING/FAILED → continue
Gate 2 (Manual Override):

text
IF subject contains "REPROCESS" → bypass Gate 1
  → route to Human Approver before any action
Layer 3 — Validation Agent (CLMS DB Read)
Runs 4 checks in sequence — all reads, no writes yet:

Step	What It Does
Bucket Resolver	Detects crew's calendar cycle → identifies active bucket and past bucket range
URTI Balance Check	Fetches URTI balance in the relevant bucket (current or past)
Roster Check	Are the dates marked SL, LWP, or Duty in CLMS?
Snapshot	Saves full before-state to internal DB (immutable audit record)
Layer 4 — Decision Router
Based on validation output, routes to one of 4 paths:

text
SL marked + URTI balance OK          → Normal Flow
Dates fall in previous bucket         → Bucket Reversal Flow
LWP marked on dates                   → LWP Escalation Flow (human required)
URTI balance insufficient             → Escalate to Human Reviewer
Normal Flow
Pull back SL from those dates

Credit SL balance back to crew

Apply URTI code on same dates

Bucket Reversal Flow
Detect which past bucket the dates fall in

Check URTI balance in that past bucket

Reverse current-bucket deduction

Apply URTI in past bucket

Reflect adjustment in current bucket too

LWP Escalation Flow
Leave is not treated as unpaid

Flag crew as eligible for arrears + efficiency bonus

Mandatorily route to human approver before write

On approval → trigger payroll team notification

Layer 5 — Dry Run (All Flows)
Before any DB write, the agent:

Computes the full before vs after diff

Example: SL -2 days | URTI +2 days | Bucket_Dec-Nov balance: 6→4

Logs this diff to internal DB

For Normal/Bucket flows → auto-proceed if diff looks valid

For LWP/REPROCESS flows → human sees this diff and clicks Approve

Layer 6 — Atomic Write Agent (CLMS DB Write)
All changes executed in a single DB transaction:

text
BEGIN TRANSACTION
  1. Reverse SL marking on dates
  2. Credit SL balance back
  3. Apply URTI code on dates
  4. Adjust bucket balances
COMMIT  ← only if all steps succeed
ROLLBACK ← if any step fails
Layer 7 — Post-Write Verification
Re-reads CLMS DB immediately after write

Compares actual state vs expected state from dry run

Match → proceed to notifications

Mismatch → immediate rollback + red alert to admin team

Layer 8 — Notification Agent
Recipient	Condition	Content
Crew Tracking Team	Always	Confirmation + updated leave details
Base Team	Always	Acknowledgement of update
Payroll Team	LWP reversed only	Arrears + efficiency bonus flag
Internal Scheduler	Always	7-day follow-up job queued
Layer 9 — 7-Day Follow-Up Job
Scheduled background job fires after 7 working days

Re-reads CLMS to confirm URTI code still intact

If discrepancy found → alert sent to Crew Tracking team automatically

Agent Summary Map
text
Email Arrives
    → [Parser Agent]        — Extract + doc check
    → [Idempotency Agent]   — Duplicate + keyword gates
    → [Validation Agent]    — CLMS read + bucket logic
    → [Decision Router]     — Normal / Bucket / LWP / Insufficient
    → [Dry Run Engine]      — Before-after diff, human approval if needed
    → [Write Agent]         — Atomic CLMS transaction
    → [Verifier Agent]      — Post-write state check + rollback if needed
    → [Notifier Agent]      — Crew Tracking, Base, Payroll, Scheduler
    → [Follow-up Job]       — 7-day CLMS confirmation
