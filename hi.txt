/* ===========================================================================
   EIS role -> permission export, for the Roles report (access_model.json)

   Purpose  : produce one row per (role, gate) so `load_profiles()` can build
              real permission profiles instead of the hypothetical archetypes
              the console ships today.
   Source   : derived by reading the procedure bodies in `EIS SP Line of
              code.sql` (DB EIS_Orig29Jul26, scripted 31 Aug 2026), chiefly
              udpEISGetPageControlAccessRights (line 48725),
              udpEISGetAccessRights (46254), udpEISGetRoles (49795) and
              udpEISGetViewEditRights (50129).
   Run as   : read-only. Nothing here writes.

   ---------------------------------------------------------------------------
   THIS SYSTEM HAS THREE PERMISSION MECHANISMS, NOT ONE
   ---------------------------------------------------------------------------
   Sections 1 and 2 cover the role/page/control grants. They are NOT the whole
   answer, and an export of them alone will overstate what people can see.

     1. ROLE GRANTS - M_Admin_Role -> RolePage -> RolePageControl.
        Drives the Add/Edit/View/Delete flags on UI controls. This is the only
        one the application code names, and the only one static analysis of the
        repository could ever have found. Sections 1 and 2 below.

     2. SUPER-USER / SERVICE CODE - EIS_UserDepartmentMapping.
        Returned by the LOGIN procedure (USP_EIS_AuthenticateUser, line
        229319) and ENFORCED server-side. udpEISGetEmployeeBasicDetail
        (46649) branches three ways on it: IsSuperUser = 1 returns every
        employee, ServiceCode = 'RML' returns only the caller's reports, and
        anything else is refused outright. udpEISGetMedicalEndorsementReport
        (48447) refuses everyone who is not a super user.
        **Zero references anywhere in the application code.** Section 3.

     3. DEPARTMENT / STATION SCOPE - M_Admin_UserStationDepartmentAccess.
        33 references in the procedures, 0 in the application code. Filters
        which departments and stations a user's results cover; `Department =
        'ALL'` is a wildcard. Section 3.

   A user's effective access is the INTERSECTION of all three. A role export
   on its own answers "which buttons are drawn", not "which rows come back".

   ---------------------------------------------------------------------------
   READ THIS BEFORE RUNNING
   ---------------------------------------------------------------------------
   1. ProjectID = 6 is mandatory. udpEISGetRoles hardcodes it and
      udpEISGetPageControlAccessRights declares @ProjectId = '6'. The role
      tables are shared with other projects; an export without this filter
      carries roles that are not EIS's.

   2. Five active flags are ANDed in the live join and all five are applied
      below. Dropping any of them OVERSTATES what a role can do:
          M_Admin_Role.Active
          M_Admin_Page.Active
          M_Admin_PageControls.ISActive
          M_Admin_RolePage.ACTIVE
          M_Admin_RolePageControl.ACTIVE

   3. The flags' DATA TYPES ARE UNKNOWN. The dump contains no CREATE TABLE for
      any of these tables, and the procedures themselves disagree: inside
      udpEISGetViewEditRights, M_Admin_RolePage.Active is compared to 'true'
      at line 50168 and to '1' at line 50212 -- same table, same procedure.
      One of those two comparisons must be returning nothing. Section 0 below
      settles it; run it first and report what it prints.

   4. The gate id is built by string concatenation, exactly as
      udpEISGetViewEditRights does it (ControlName + AccessName, then spaces
      stripped). 31 of the 46 gates the pipeline found match this convention
      character for character, which is what confirms the mapping.
   =========================================================================== */


/* ---------------------------------------------------------------------------
   SECTION 0 -- PREFLIGHT. Run this first and send the output back.
   It resolves the type ambiguity in note 3 and confirms the tables are
   populated at all. It is the cheapest way to avoid a silently empty export.
   --------------------------------------------------------------------------- */
SELECT  c.TABLE_NAME, c.COLUMN_NAME, c.DATA_TYPE, c.CHARACTER_MAXIMUM_LENGTH
FROM    INFORMATION_SCHEMA.COLUMNS c
WHERE   c.TABLE_NAME IN ('M_Admin_Role','M_Admin_Page','M_Admin_PageControls',
                         'M_Admin_RolePage','M_Admin_RolePageControl',
                         'M_Admin_MasterPage','M_Admin_User','M_Admin_UserRole',
                         -- mechanisms 2 and 3; column lists below are inferred
                         -- from procedure USAGE, since the dump carries no DDL
                         'EIS_UserDepartmentMapping',
                         'M_Admin_UserStationDepartmentAccess',
                         'M_Admin_Project')
ORDER BY c.TABLE_NAME, c.ORDINAL_POSITION;

-- Confirm EIS really is ProjectID 6. udpEISGetRoles hardcodes 6, but the login
-- procedure looks it up by name - so the two disagree if this returns anything
-- other than 6, and the login path is the one to trust.
SELECT ProjectId, ProjectName FROM M_Admin_Project (NOLOCK) WHERE ProjectName = 'EIS';

SELECT 'M_Admin_Role'           AS TableName, COUNT(*) AS Rows_All,
        SUM(CASE WHEN ProjectID = 6 THEN 1 ELSE 0 END) AS Rows_Project6
FROM    M_Admin_Role (NOLOCK)
UNION ALL SELECT 'M_Admin_RolePage',        COUNT(*), NULL FROM M_Admin_RolePage (NOLOCK)
UNION ALL SELECT 'M_Admin_RolePageControl', COUNT(*), NULL FROM M_Admin_RolePageControl (NOLOCK)
UNION ALL SELECT 'M_Admin_PageControls',    COUNT(*), NULL FROM M_Admin_PageControls (NOLOCK)
UNION ALL SELECT 'M_Admin_Page',            COUNT(*), NULL FROM M_Admin_Page (NOLOCK)
UNION ALL SELECT 'EIS_UserDepartmentMapping', COUNT(*),
        SUM(CASE WHEN IsSuperUser = 1 THEN 1 ELSE 0 END)  -- how many are SUPER USERS
FROM      EIS_UserDepartmentMapping (NOLOCK)
UNION ALL SELECT 'M_Admin_UserStationDepartmentAccess', COUNT(*), NULL
FROM      M_Admin_UserStationDepartmentAccess (NOLOCK);

/* The Rows_Project6 column on the EIS_UserDepartmentMapping row is the
   super-user count, not a project count. Worth looking at closely:
   udpEISInsertUser (line 51069) creates EVERY new user with IsSuperUser = 1
   and UserPassword = '1', so this number may be far larger than anyone
   expects. If it equals the row count, every user is a super user and
   mechanism 2 grants everything to everybody. */

-- what the flags actually contain, as text
SELECT DISTINCT 'M_Admin_RolePage.ACTIVE'        AS Flag, CONVERT(nvarchar(20), ACTIVE) AS Value FROM M_Admin_RolePage (NOLOCK)
UNION ALL SELECT DISTINCT 'M_Admin_RolePageControl.ACTIVE', CONVERT(nvarchar(20), ACTIVE) FROM M_Admin_RolePageControl (NOLOCK)
UNION ALL SELECT DISTINCT 'M_Admin_Role.Active',            CONVERT(nvarchar(20), Active) FROM M_Admin_Role (NOLOCK)
UNION ALL SELECT DISTINCT 'M_Admin_Page.Active',            CONVERT(nvarchar(20), Active) FROM M_Admin_Page (NOLOCK)
UNION ALL SELECT DISTINCT 'M_Admin_PageControls.ISActive',  CONVERT(nvarchar(20), ISActive) FROM M_Admin_PageControls (NOLOCK);


/* ---------------------------------------------------------------------------
   SECTION 1 -- THE EXPORT.

   Every active-flag test goes through CONVERT(nvarchar) so it behaves the same
   whether the column is bit, char or nvarchar. That is deliberate: see note 3.
   Do not "simplify" these to = 1.
   --------------------------------------------------------------------------- */
WITH ActiveGrant AS (
    SELECT  r.RoleID,
            r.RoleName,
            mp.MPageName                    AS PageNameAsCalled,   -- what the app passes
            p.PageName                      AS PageNameInternal,
            pc.ControlName,
            rpc.[ADD]    AS GrantAdd,
            rpc.[EDIT]   AS GrantEdit,
            rpc.[VIEW]   AS GrantView,
            rpc.[DELETE] AS GrantDelete
    FROM        M_Admin_RolePageControl rpc (NOLOCK)
    INNER JOIN  M_Admin_RolePage        rp  (NOLOCK) ON rp.RolePageID   = rpc.RolePageID
    INNER JOIN  M_Admin_Role            r   (NOLOCK) ON r.RoleID        = rp.RoleID
    INNER JOIN  M_Admin_Page            p   (NOLOCK) ON p.PageID        = rp.PageID
    INNER JOIN  M_Admin_PageControls    pc  (NOLOCK) ON pc.PageID       = p.PageID
                                                    AND pc.PageControlID = rpc.PageControlID
    LEFT  JOIN  M_Admin_MasterPage      mp  (NOLOCK) ON mp.MPageID      = p.MPageID
                                                    AND mp.ProjectID    = r.ProjectID
    WHERE   r.ProjectID = 6                                                   -- note 1
      AND   UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), r.Active))))    IN ('1','TRUE','Y','YES')
      AND   UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), p.Active))))    IN ('1','TRUE','Y','YES')
      AND   UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), pc.ISActive)))) IN ('1','TRUE','Y','YES')
      AND   UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), rp.ACTIVE))))   IN ('1','TRUE','Y','YES')
      AND   UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), rpc.ACTIVE))))  IN ('1','TRUE','Y','YES')
),
/* Control-level gates. The id is ControlName + 'Control' + Verb + 'Access',
   spaces stripped -- the concatenation udpEISGetViewEditRights performs at
   lines 50253 and 50268. This produces 31 of the 46 gates the scan found. */
ControlGates AS (
    SELECT RoleID, RoleName, PageNameAsCalled, PageNameInternal, ControlName,
           REPLACE(ControlName, ' ', '') + 'ControlAddAccess'    AS gate, GrantAdd    AS raw FROM ActiveGrant
    UNION ALL
    SELECT RoleID, RoleName, PageNameAsCalled, PageNameInternal, ControlName,
           REPLACE(ControlName, ' ', '') + 'ControlEditAccess',   GrantEdit   FROM ActiveGrant
    UNION ALL
    SELECT RoleID, RoleName, PageNameAsCalled, PageNameInternal, ControlName,
           REPLACE(ControlName, ' ', '') + 'ControlViewAccess',   GrantView   FROM ActiveGrant
    UNION ALL
    SELECT RoleID, RoleName, PageNameAsCalled, PageNameInternal, ControlName,
           REPLACE(ControlName, ' ', '') + 'ControlDeleteAccess', GrantDelete FROM ActiveGrant
),
/* Page-level gates. M_Admin_RolePage carries its OWN [Add]/[Edit]/[View]
   columns -- a second tier of grant that sits above the control-level one and
   that the four Markdown documents never mention. udpEISGetViewEditRights
   emits these as the literals 'PageAddAccess' / 'PageEditAccess' /
   'PageViewAccess' (lines 50257-50261). PageViewAccess is one of the 46. */
PageGates AS (
    SELECT  r.RoleID, r.RoleName, mp.MPageName AS PageNameAsCalled,
            p.PageName AS PageNameInternal,
            CAST(NULL AS nvarchar(100)) AS ControlName,   -- typed: UNION ALL needs it
            v.gate, v.raw
    FROM        M_Admin_RolePage rp (NOLOCK)
    INNER JOIN  M_Admin_Role     r  (NOLOCK) ON r.RoleID = rp.RoleID
    INNER JOIN  M_Admin_Page     p  (NOLOCK) ON p.PageID = rp.PageID
    LEFT  JOIN  M_Admin_MasterPage mp (NOLOCK) ON mp.MPageID = p.MPageID
                                              AND mp.ProjectID = r.ProjectID
    CROSS APPLY (VALUES ('PageAddAccess',  rp.[Add]),
                        ('PageEditAccess', rp.[Edit]),
                        ('PageViewAccess', rp.[View])) AS v(gate, raw)
    WHERE   r.ProjectID = 6
      AND   UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), r.Active))))  IN ('1','TRUE','Y','YES')
      AND   UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), p.Active))))  IN ('1','TRUE','Y','YES')
      AND   UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), rp.ACTIVE)))) IN ('1','TRUE','Y','YES')
)
SELECT      RoleID,
            RoleName                AS role,
            PageNameAsCalled,
            PageNameInternal,
            ControlName,
            gate,
            CASE WHEN UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), raw))))
                      IN ('1','TRUE','Y','YES') THEN 1 ELSE 0 END AS allowed
FROM        (SELECT * FROM ControlGates UNION ALL SELECT * FROM PageGates) g
ORDER BY    role, gate;


/* ---------------------------------------------------------------------------
   SECTION 2 -- WHO HOLDS WHICH ROLE (optional; answers a different question)

   There are TWO user->role paths in the dump and they are not the same table.
   Export both and expect them to disagree; which one is authoritative is a
   question for whoever owns the app, not something the source settles.

   NOTE: udpEISGetUserRoleName (line 50066) applies NEITHER the ProjectID
   filter NOR any Active flag. The filters are added here deliberately; if you
   want to reproduce what the application actually sees, remove them.
   --------------------------------------------------------------------------- */
-- path A: the admin user table, used by udpEISGetUserRoleName / udpEISGetViewEditRights
SELECT      au.UserName, r.RoleID, r.RoleName
FROM        M_Admin_User     au  (NOLOCK)
INNER JOIN  M_Admin_UserRole aur (NOLOCK) ON aur.UserID = au.UserID
INNER JOIN  M_Admin_Role     r   (NOLOCK) ON r.RoleID   = aur.RoleID
WHERE       r.ProjectID = 6
  AND       UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), r.Active)))) IN ('1','TRUE','Y','YES')
ORDER BY    r.RoleName, au.UserName;

-- path B: the employee mapping table, used by udpEmployeeRole and ~10 others
SELECT      m.EmployeeCode, r.RoleID, r.RoleName
FROM        MstEmployeeRoleMapping m (NOLOCK)
INNER JOIN  M_Admin_Role r (NOLOCK) ON r.RoleID = m.RoleID
WHERE       r.ProjectID = 6
ORDER BY    r.RoleName, m.EmployeeCode;


/* ---------------------------------------------------------------------------
   SECTION 3 -- THE TWO MECHANISMS THAT ACTUALLY REFUSE PEOPLE

   Sections 1 and 2 describe which controls a ROLE may use. This section
   describes what a USER can actually retrieve, and the two disagree: a user
   whose role grants every control still gets 'UserIsNotSuperUserORServiceCode
   IsNotRML' from udpEISGetEmployeeBasicDetail unless mechanism 2 allows it.

   Note the axis change. Mechanisms 2 and 3 are keyed by USER, not by role -
   there is no role column in either table. So "what can a Crew Admin see" is
   not answerable from them at all; only "what can this named user see" is.
   That is a finding in itself and should be reported, not worked around.
   --------------------------------------------------------------------------- */

-- 3a. Effective privilege per user: the super-user flag and the service code.
--     IsSuperUser = 1                -> every employee (Generic path)
--     ServiceCode = 'RML'            -> only the caller's direct reports
--     neither                        -> refused
--     'RML' is the ONLY ServiceCode value tested anywhere in 1,172 procedures.
--     Any other value behaves exactly like "neither"; list them so nobody
--     assumes a code is doing something it is not.
SELECT      au.UserID,
            au.UserName,
            au.Active                       AS UserActive,
            udm.IsSuperUser,
            udm.ServiceCode,
            udm.ServiceDescription,
            CASE WHEN udm.UserID IS NULL            THEN 'no row - refused'
                 WHEN udm.IsSuperUser = 1           THEN 'all employees'
                 WHEN udm.ServiceCode = 'RML'       THEN 'own reports only'
                 ELSE 'refused'
            END                             AS EffectiveEmployeeScope
FROM        M_Admin_User au (NOLOCK)
LEFT  JOIN  EIS_UserDepartmentMapping udm (NOLOCK) ON udm.UserID = au.UserID
WHERE       au.ProjectID = (SELECT ProjectId FROM M_Admin_Project (NOLOCK)
                            WHERE ProjectName = 'EIS')
  AND       UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), au.Active)))) IN ('1','TRUE','Y','YES')
ORDER BY    udm.IsSuperUser DESC, au.UserName;

-- 3b. Department and station scope per user.
--     THIS ONE FAILS OPEN, so read the result the right way round.
--     udpEISGetDepartment (line 46431) asks whether the user has any row whose
--     Department is neither blank nor 'ALL'. If such rows exist the user is
--     RESTRICTED to them. If NONE exist, the procedure returns every row of
--     MstDepartment - the whole organisation.
--     So a user with NO mapping row has MORE access than one with a row, and
--     'ALL' is a wildcard in the sense that it is skipped by the test rather
--     than granted by it. An empty result in this section means unrestricted,
--     not unprivileged; do not read it as "this user has no access".
SELECT      au.UserName,
            da.Department,
            da.DepartmentDesc,
            da.Station,
            da.Active,
            CASE WHEN da.Department = 'ALL' THEN 'all departments'
                 WHEN da.Department IS NULL OR da.Department = '' THEN 'none recorded'
                 ELSE 'restricted to the listed departments'
            END                             AS DepartmentScope
FROM        M_Admin_User au (NOLOCK)
LEFT  JOIN  M_Admin_UserStationDepartmentAccess da (NOLOCK)
                 ON da.UserID = au.UserID AND da.ProjectID = au.ProjectID
WHERE       au.ProjectID = (SELECT ProjectId FROM M_Admin_Project (NOLOCK)
                            WHERE ProjectName = 'EIS')
  AND       UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), au.Active)))) IN ('1','TRUE','Y','YES')
ORDER BY    au.UserName, da.Department, da.Station;

-- 3c. The one row that matters most: how many users are super users.
--     See the note in section 0. If this is close to the total, mechanism 2
--     is not restricting anybody and the role grants in section 1 are the
--     only thing standing between a user and the data.
SELECT      COUNT(*)                                                   AS EISUsers,
            SUM(CASE WHEN udm.IsSuperUser = 1 THEN 1 ELSE 0 END)       AS SuperUsers,
            SUM(CASE WHEN udm.ServiceCode = 'RML' THEN 1 ELSE 0 END)   AS ReportingManagerOnly,
            SUM(CASE WHEN udm.UserID IS NULL THEN 1 ELSE 0 END)        AS NoMappingRow_Refused
FROM        M_Admin_User au (NOLOCK)
LEFT  JOIN  EIS_UserDepartmentMapping udm (NOLOCK) ON udm.UserID = au.UserID
WHERE       au.ProjectID = (SELECT ProjectId FROM M_Admin_Project (NOLOCK)
                            WHERE ProjectName = 'EIS')
  AND       UPPER(LTRIM(RTRIM(CONVERT(nvarchar(20), au.Active)))) IN ('1','TRUE','Y','YES');
