I can see exactly what's happening here. This is a well-known issue with Expo SDK 54 + React Native 0.76 (New Architecture / Bridgeless mode) running in Expo Go. The PlatformConstants TurboModule isn't registering correctly due to a mismatch. Here's the full diagnosis and fix:

Root Cause
Your react-native: 0.76.5 uses the New Architecture (Bridgeless mode = true) by default, but Expo Go on your phone may not be fully compatible with how your project initializes native modules. The PlatformConstants module is needed by react-native-paper and react-native-safe-area-context, but it crashes before the native binary can register it.

Additionally, your company network is blocking ngrok/tunnels entirely — that's a separate but already-solved problem. The crash happens even after the bundle loads, meaning the connection is fine but the JS runtime is failing.
​

Fix 1 — Disable New Architecture (Fastest Fix)
Add this to your app.json inside the "expo" key:

json
"experiments": {
  "newArchEnabled": false
}
Your full app.json "expo" block should include:

json
"experiments": {
  "newArchEnabled": false
},
"android": { ... },
"ios": { ... }
Then run:

text
rmdir /s /q node_modules
npm install
npx expo start --offline --clear
This disables Bridgeless mode and makes PlatformConstants register correctly in Expo Go.

Fix 2 — Reinstall expo-modules-core Explicitly
If Fix 1 alone doesn't work, also run:
​

text
npx expo install expo-modules-core
npx expo install expo-modules-core@~2.0.0
Then clear and restart:

text
npx expo start --offline --clear
Fix 3 — Downgrade react-native-paper
react-native-paper ^5.12.0 has known issues with New Architecture in some Expo SDK 54 setups. Pin it to a known-good version in package.json:
​

json
"react-native-paper": "5.12.3"
Then:

text
npm install
npx expo start --offline --clear
About the Network Issue
Your company network (IndiGo) is blocking:

ngrok (tunnel times out)
​

Expo's online API calls (TypeError: fetch failed)
​

--offline + --lan are conflicting flags — you already discovered that. The correct command is just:

text
set EXPO_OFFLINE=1
npx expo start --lan --clear
Then manually type in Expo Go app → "Enter URL manually":

text
exp://172.30.100.108:8081
This should work as long as your phone and laptop are on the same WiFi network. The EXPO_OFFLINE=1 env var suppresses the external API calls that were causing the fetch failed errors.
​
